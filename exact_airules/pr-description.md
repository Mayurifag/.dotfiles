# PR Descriptions

- Follow repo PR templates; otherwise use `## Problem` (concrete issue/gap/risk/confusion) and `## What Changed` (exact
  changes; relevant user-visible behavior, config, migrations, compatibility, and risks).
- Name behavior, files, flows, APIs, commands, or settings when useful; use direct verbs, not commit summaries.
- Add `Validation`, `Testing`, or test commands only on request or template requirement.
- No filler: `This PR introduces`, `enhances`, `improves`, `various fixes`, `better maintainability`.
